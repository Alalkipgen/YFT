# Video Downloader 1.0.0-beta.3

**Third beta for sideload testing: the fixes from the beta.2 phone test, the copied-link flow and
more YouTube formats, including MP3.** It completes Phases 8–10 of the fix plan
(`docs/FIX_PLAN.md`). Video Downloader (YFT) is an ad-free Android app that detects, previews
and downloads public, non-DRM media from links, HTML5 players, HLS and DASH streams. It never bypasses DRM, payment, private content or age checks, and its site adapters
never sign in.

## Requirements

- Android 7.0 (API 24) or newer; built for Android 15 (API 35).
- A network connection. The in-app browser loads HTTPS pages only.

## Install

1. Download `video-downloader-1.0.0-beta.3.apk` and `SHA256SUMS` from the release assets.
2. Check the file against the SHA-256 under "Verify the download" below:
   - Linux: `sha256sum -c SHA256SUMS`
   - macOS: `shasum -a 256 -c SHA256SUMS`
   - Windows PowerShell: `Get-FileHash .\video-downloader-1.0.0-beta.3.apk -Algorithm SHA256`
3. Open the APK on the phone. When Android asks, allow your browser or file manager to install
   unknown apps (Settings › Apps › Special app access › Install unknown apps).
4. Optional: `apksigner verify --print-certs video-downloader-1.0.0-beta.3.apk` should print the
   signing certificate SHA-256 shown below.
5. On Android 13 or newer, allow notifications so download progress and controls are visible.

1.0.0-beta.3 is signed with the same key as 1.0.0-beta.1 and 1.0.0-beta.2 and has version code 3,
so it installs over beta.2 or beta.1 and keeps settings and downloads. If Android refuses the
update, the installed copy was signed with a different key; uninstalling it first deletes its
settings and app-private downloads. Test builds from CI (`yft-debug-apk`) install separately as
`com.alal.yft.debug` and are not replaced.

## What's new

### Fixes from the beta.2 phone test (Phase 8)

- The in-app browser no longer closes the app when a page loads.
- The empty browser shows a start page with the address bar, tap-to-paste and Your sites; the
  address bar and X stay visible above the page.
- Facebook public reels, videos and share links are found (HD, SD and the page's DASH tracks)
  instead of asking to sign in or failing as DRM-protected.
- TikTok videos found from a pasted link download instead of failing with HTTP 403.
- YouTube tells a bot check from a real sign-in and says what to do; answers that offer only
  SABR streaming fail with their own detail.
- Home lookups use an honest YFT identity, and a failed lookup offers **Copy details** (steps
  and statuses without addresses, cookies or session values).
- About › Last crash report keeps one redacted crash report on the phone to View, Copy, Share
  text or Delete. Nothing is sent automatically.
- Your sites start with YouTube, Facebook and TikTok, shown with their logos.

### Copied-link flow (Phase 9)

- Check copied links: when YFT opens with a new copied link, Home looks it up straight away.
  Settings › Privacy has a switch to turn it off.
- "Video you copied": when a link finds one video, a sheet offers Music (M4A), Fast (up to
  480p) and High (up to 720p) with real sizes, More formats and one Download button.
- Search to download: Home opens the browser's start page ready to type. Words offer "Search
  YouTube" and "Search the web" (DuckDuckGo); a link opens. View sites shows YouTube,
  Facebook, TikTok, Instagram and X, with View all for your sites.
- Browser Download button: a Mint button appears when the page has a video you can save. One
  video opens "Video you copied"; several open "Found on this page", with a count badge.

### YouTube and formats (Phase 10)

- YouTube lookups ask more of YouTube's clients: its visionOS and Android app clients, the
  embedded player, the page's own web client with your session and a proof-of-origin token
  from YouTube's BotGuard, and finally the mobile site. In YFT's browser a bot check offers
  **Try again**, and the lookup also runs once by itself after the video starts playing.
- YouTube 480p, 720p and 1080p with sound: YFT downloads the video-only MP4 and the M4A audio
  (in requests of at most 10 MiB) and merges them on the phone into one MP4. These rows show a
  **Video + audio** chip and preview with sound.
- MP3: save a video's audio as MP3 (192 or 128 kbps) from "Video you copied" or Download as.
  The M4A is converted on the phone with LAME 3.100 and gets its title.

## Privacy

No ads, analytics, accounts or cloud backup. HTTPS only. Detected links stay in memory, and logs
never contain cookies, tokens or signed links. The clipboard is read when Paste or Use is tapped
and, while Check copied links is on, once when YFT opens with a new copied link; only the first
web link is used and the copied text is never stored (Android 12 and newer show their own paste
message). TikTok's page cookies and YouTube's proof-of-origin tokens stay in memory and go only
to that site's own servers. The crash report stays on the phone and is never sent
automatically. About › Licenses lists every third-party license, including LAME (LGPL) for MP3.

## Known issues

- YouTube changes often. Bot checks still happen on some networks (in YFT's browser, let the
  video play for a moment or tap **Try again**), and the client profiles, the player-script
  solver and the token host need regular updates.
- Merged YouTube qualities need AVC video and AAC audio, because the phone's muxer writes
  nothing else; VP9 and AV1 are not offered, so some videos stop below 1080p. Both files must
  fit on the phone until they are merged.
- MP3 is converted on the phone after the M4A download and only from AAC audio; long files
  take a while and need room for both files during the conversion. The MP3 size is an estimate.
- Separate video and audio tracks from other sites are combined only for AVC/AAC in MP4/fMP4.
  DASH `SegmentBase`/SIDX and live streams are not supported.
- Saving to an arbitrary folder through the system picker is not available yet.
- An unfinished download whose link expired while the app was closed needs a fresh link from
  the page.
- The free-space check covers only exact sizes; estimated or unknown sizes stop cleanly if
  storage fills up.
- TikTok, Facebook and Vimeo support is verified against saved page fixtures and a few live
  links; site changes can break it.
- Playback in the Library and Downloads stops when YFT leaves the screen; there is no
  background playback.
- Downloads shows speed and time left only while the Downloads screen is open.

## Phone checklist

Please run these with this APK on a phone and report what fails.

Phase 8 — field fixes:

1. Install over beta.2 (same signing key); the app opens.
2. Home shows YouTube, Facebook and TikTok with logos. Tapping each opens it in the browser
   without a crash, with the address bar and X visible.
3. Home › Open browser shows the start page with the address bar; typing `example.com` loads it.
4. Paste a Facebook share link → found (HD/SD) → download → it plays in the Library.
5. Paste a TikTok link → found → download → it plays.
6. Paste a YouTube link → found, or the new message → **Copy details** → send them to the
   maintainers.
7. About › Last crash report: none (if there is one, Share it).

Phase 9 — copied-link flow:

8. Copy a link in another app → open YFT → the "Video you copied" sheet appears by itself
   (Android shows its paste message) → Fast, High or Music → Download.
9. Home › Search to download: type words → Search YouTube or Search the web; a link opens;
   View sites lists the sites.
10. Open a video page in the browser → the Mint Download button appears → it opens "Video you
    copied" or "Found on this page".

Phase 10 — formats and YouTube:

11. A YouTube 720p **Video + audio** download plays with sound.
12. An MP3 from "Video you copied" or Download as plays in another app with its title.

## Testing status

This beta passed the automated JVM, Robolectric and fixture tests (core-model 54, core-download
104, core-media 17, core-data 16, extractor-api 32, extractor-generic 8, extractor-sites 150 and
app 542 with 66 render-only tests skipped; 0 failures), Android lint with no errors, the Android
14 emulator jobs in CI (real WebView browser checks and the MP3 conversion), the minified release
build and APK signature verification. Live checks from a data-centre network found a public
Facebook share link (HD, SD and DASH), TikTok media with the page's cookies and YouTube through
its app and mobile clients; one YouTube test video stayed bot-checked there. It has **not** yet
been tested on a phone by the maintainers: please run the checklist above and report problems
through GitHub issues with the Android version, device model and the site's domain (never a
signed link, cookie or account detail).
