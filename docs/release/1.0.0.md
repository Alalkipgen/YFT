# Video Downloader 1.0.0

**The first stable release.** Video Downloader (YFT) is an ad-free Android app that detects,
previews and downloads public, non-DRM media from links, HTML5 players, HLS and DASH streams. It
never bypasses DRM, payment, private content or age checks, and its site adapters never sign in.
1.0.0 brings everything since `1.0.0-beta.3`: the download flow and fixes of Phases 11–15, X and
Instagram, TikTok from TikTok's own pages, VK, a backup finder for the sites' changes, and updates
inside the app.

## Requirements

- Android 7.0 (API 24) or newer; built for Android 15 (API 35).
- A network connection. The in-app browser loads HTTPS pages only.

## Install

1. Download `video-downloader-1.0.0.apk` and `SHA256SUMS` from the release assets.
2. Check the file against the SHA-256 under "Verify the download" below:
   - Linux: `sha256sum -c SHA256SUMS`
   - macOS: `shasum -a 256 -c SHA256SUMS`
   - Windows PowerShell: `Get-FileHash .\video-downloader-1.0.0.apk -Algorithm SHA256`
3. Open the APK on the phone. When Android asks, allow your browser or file manager to install
   unknown apps (Settings › Apps › Special app access › Install unknown apps).
4. Optional: `apksigner verify --print-certs video-downloader-1.0.0.apk` should print the signing
   certificate SHA-256 shown below.
5. On Android 13 or newer, allow notifications so download progress and controls are visible.

1.0.0 is signed with the same key as the betas and has version code 1000000 (the version code
rule in `docs/RELEASE.md`), so it installs over any beta and keeps settings and downloads. If
Android refuses the update, the installed copy was signed with a different key; uninstalling it
first deletes its settings and app-private downloads. Test builds install separately and are not
replaced: `com.alal.yft.debug`, "YFT Preview" (`com.alal.yft.preview`) and "YFT Trial"
(`com.alal.yft.trial`).

From 1.0.0 on, YFT tells you when a new version is out (Settings → About → Updates), with its
release notes, and installs it after checking its checksum and signature, with Android's
confirmation.

## What's new

### Finding videos

- **Backup finder:** when a site's own lookup finds no video, YFT tries other ways — for YouTube
  its own player-script solver and more of YouTube's clients; for Facebook, TikTok, Instagram and
  X each site's own player or embed page, the lookup's own answers read again, then the video
  the page plays (play it, then tap Download again). It acts only after the site's own lookup
  failed, so a video that lookup finds is found as before. Its site data can be updated from
  GitHub, only by a file signed with the key YFT carries. **Settings → Backup finder** is on by
  default; off, no lookup asks it and nothing goes to GitHub for it.
- **VK:** public videos and clips on vk.com, vk.ru and vkvideo.ru, up to 2160p, with their
  Russian titles; public 18+ VK videos that VK's embed refuses are found through vkvideo.ru's own
  signed-out API.
- **X and Instagram:** every MP4 quality of an X post's video, with sound; Instagram reels and
  video posts (Home uses the Instagram sign-in of YFT's browser, when there is one).
- **TikTok** is read from TikTok's own pages and the tab's data: every height its pages give,
  public posts its phone page calls private, and **Show check** when TikTok wants to check that
  you are not a bot (you answer it; YFT never does).
- **Other sites:** the page's own video instead of the ad before it, fresh links instead of HTTP
  410, HLS with its sound in a separate playlist.

### Downloading

- One short download sheet for every site, with real qualities, sizes and pictures; YouTube up to
  2160p, Facebook in every size it gives.
- Downloads, merges and MP3 conversions keep going in the background, with speed in the
  notification; Delete file in Downloads; Retry says what failed and where.
- HLS downloads are saved as `.mp4` (`.m4a` for sound alone), never as `.m3u8`, and every
  finished download shows the size of the file it saved.
- Audio: YouTube offers M4A and MP3 320, 192 and 128 kbps; every other site M4A and MP3 192.
- Myanmar titles keep their marks in file names.
- Home's sites start with YouTube, Facebook, TikTok, Instagram and X.

### A quiet app

- The browser shows no lookup notices or Try again, and the download sheet says one line when a
  video can't be got: "Couldn't get this video.", TikTok's check with **Show check**, or "Play the
  video, then tap Download again." A failed download keeps its retry.
- When a maintainer asks for a failure's details: tap the version line in About 7 times ("Show
  details on" appears under it); the sheet then shows Details and Copy details. Tap it 7 times
  again to turn them off.

## Privacy

No ads, analytics, accounts or cloud backup. HTTPS only. YFT only contacts the sites you open, the
media servers they point to and GitHub: with Backup finder on, a lookup the site doesn't answer
may read YFT's site data from GitHub (raw.githubusercontent.com); with Check automatically on
(Settings → About → Updates; on until you turn it off), YFT asks GitHub (api.github.com) about its
newest release once a day, when it opens. Nothing about you or your downloads is sent. Detected links stay in
memory, and logs never contain cookies, tokens or signed links. A site's cookies and tokens stay
in memory and go only to that site's own servers. The crash report stays on the phone and is
never sent automatically. About › Licenses lists every third-party license.

## Known issues

- Sites change often. YouTube's bot checks still happen on some networks (in YFT's browser, let
  the video play for a moment), and a site's change can stop its lookup until a fix; the backup
  finder covers some changes, a site data update from GitHub others.
- Merged qualities need AVC video and AAC audio, because the phone's muxer writes nothing else;
  VP9 and AV1 are not offered, so some videos stop below their highest quality.
- Instagram posts that only signed-in viewers see need YFT's browser signed in to Instagram;
  X's protected and age-limited posts are not found.
- DASH `SegmentBase`/SIDX and live streams are not supported; saving to an arbitrary folder
  through the system picker is not available yet.
- The update check and the in-app install need GitHub to be reachable; when an install fails,
  **Download in browser** opens the release's APK.
