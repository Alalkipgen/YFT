# Video Downloader 1.0.1

**The backup finder for VK, and fixes to what it offers on every site.** Video Downloader (YFT) is
an ad-free Android app that detects, previews and downloads public, non-DRM media from links, HTML5
players, HLS and DASH streams. It never bypasses DRM, payment, private content or age checks, and
its site adapters never sign in. 1.0.1 adds VK to the backup finder and fixes the rows it offers;
the sites' own lookups are as in 1.0.0.

## Requirements

- Android 7.0 (API 24) or newer; built for Android 15 (API 35).
- A network connection. The in-app browser loads HTTPS pages only.

## Install

**From 1.0.0:** Settings → About → Updates offers 1.0.1; YFT checks its checksum and signature, then
Android asks you to confirm. Settings and downloads stay.

By hand:

1. Download `video-downloader-1.0.1.apk` and `SHA256SUMS` from the release assets.
2. Check the file against the SHA-256 under "Verify the download" below:
   - Linux: `sha256sum -c SHA256SUMS`
   - macOS: `shasum -a 256 -c SHA256SUMS`
   - Windows PowerShell: `Get-FileHash .\video-downloader-1.0.1.apk -Algorithm SHA256`
3. Open the APK on the phone. When Android asks, allow your browser or file manager to install
   unknown apps (Settings › Apps › Special app access › Install unknown apps).
4. Optional: `apksigner verify --print-certs video-downloader-1.0.1.apk` should print the signing
   certificate SHA-256 shown below.
5. On Android 13 or newer, allow notifications so download progress and controls are visible.

1.0.1 is signed with the same key as 1.0.0 and has version code 1000100 (the version code rule in
`docs/RELEASE.md`), so it installs over 1.0.0 and keeps settings and downloads. If Android refuses
the update, the installed copy was signed with a different key; uninstalling it first deletes its
settings and app-private downloads. Test builds install separately and are not replaced:
`com.alal.yft.debug`, "YFT Preview" (`com.alal.yft.preview`) and "YFT Trial" (`com.alal.yft.trial`).

## What's new

### Finding videos

- **Backup finder for VK:** when VK's own lookup finds no video, YFT now tries VK's own ways too —
  the lookup's own VK pages read again; when VK refuses YFT's copy of its web player's settings, the
  current ones read from vkvideo.ru (at most once a day), then one more ask; then the video the page
  plays (play it, then tap Download again), also when VK's player hides inside its page, gives only
  a DASH manifest or the page's own video data, or plays the video in pieces (YFT checks their whole
  files and merges the picture with its sound). It acts only after VK's own lookup failed, so a
  video that lookup finds is found as before. **Settings → Backup finder** covers VK like the other
  sites; VK's site data can be updated from GitHub, only by a file signed with the key YFT carries.
- **Lookup details after a success:** with Show details on (tap the version line in About 7 times),
  the download sheet also shows the backup finder's **Lookup details** under the rows it found, with
  **Copy details**.

### Fixes

- The backup finder never offers a piece of a video (a part the player asked for) as a download row,
  on any site; before, a VK video could show a row of a few KB.
- The download sheet offers a merged quality only when the phone can combine its video and sound —
  the same check the download makes — so a download is no longer refused with "This video and its
  audio cannot be combined on this phone" after the sheet offered it. When VK doesn't state a file's
  codec, YFT reads it from the file's own start.
- A read of VK's settings cut short (a closed page, the lookup's time limit, no network) no longer
  uses up the day's one read.

## Privacy

No ads, analytics, accounts or cloud backup. HTTPS only. YFT only contacts the sites you open, the
media servers they point to and GitHub: with Backup finder on, a lookup the site doesn't answer
may read YFT's site data from GitHub (raw.githubusercontent.com); with Check automatically on
(Settings → About → Updates; on until you turn it off), YFT asks GitHub (api.github.com) about its
newest release once a day, when it opens. Nothing about you or your downloads is sent. Detected links stay in
memory, and logs never contain cookies, tokens or signed links. A site's cookies and tokens stay
in memory and go only to that site's own servers. The crash report stays on the phone and is
never sent automatically. About › Licenses lists every third-party license.

## Known issues

- Sites change often. YouTube's bot checks still happen on some networks (in YFT's browser, let
  the video play for a moment), and a site's change can stop its lookup until a fix; the backup
  finder covers some changes, a site data update from GitHub others.
- Merged qualities need AVC video and AAC audio, because the phone's muxer writes nothing else;
  VP9 and AV1 are not offered, so some videos stop below their highest quality.
- Instagram posts that only signed-in viewers see need YFT's browser signed in to Instagram;
  X's protected and age-limited posts are not found.
- VK Sport links (vksport.vkvideo.ru) are not handled yet.
- During two or three downloads at once, the Downloads list's rows can swap places while they
  progress.
- DASH `SegmentBase`/SIDX and live streams are not supported; saving to an arbitrary folder
  through the system picker is not available yet.
- The update check and the in-app install need GitHub to be reachable; when an install fails,
  **Download in browser** opens the release's APK.
